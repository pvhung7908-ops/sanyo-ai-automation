# Brand Context Boundary

Brand strategy, claims, customer positioning and voice are owned by **System 1**. System 2 must receive only the approved, job-specific context it needs through the bridge contract.

## Runtime requirements

- Each job carries verified source references; a reference is evidence, not a copied knowledge record.
- Brand-critical and product-critical assets must have status APPROVED.
- Unsupported claims, specifications, certifications and testimonials are rejected or sent to human review.
- Production prompts may reference approved System 1 source material, but System 2 must not rewrite or maintain a competing brand profile.

System 2 applies brand context during production; it does not authoritatively define it.
